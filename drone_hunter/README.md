# drone_hunter

Програма керування ударним дроном: вибирає ціль, веде дрон до точки скиду
і в потрібний момент скидає боєприпас так, щоб балістична траєкторія
закінчилась на цілі.

Проєкт наростав від домашньої роботи до домашньої роботи: від простої
симуляції в одному потоці до багатопотокової програми, яка працює з
зовнішнім симулятором фізики на Raspberry Pi по UART/GPIO і передає
телеметрію в наземну станцію по MAVLink.

## Як це працює

```
 джерело даних              ядро                          вихід

| JSON-файли  |      | MissionProcessor          |      | simulation.json   |
|   або       | ---> |  - вибір цілі + прогноз   | ---> | GPIO DROP         |
| UART-канал  |      |  - балістичний розрахунок |      | MAVLink (UDP)     |
|             |      |  - стейт-машина дрона     |      | HTTP-звіт         |
```

Кожен такт `MissionProcessor`:

1. отримує поточні позиції цілей і прогнозує, де ціль буде в момент
   влучання;
2. обирає ціль, до якої найшвидше долетіти;
3. рахує точку скиду через балістичний солвер (час падіння і
   горизонтальний виліт боєприпасу з урахуванням висоти, швидкості,
   маси, опору та підйомної сили);
4. через стейт-машину (`Stopped`, `Accelerating`, `Moving`, `Turning`,
   `Decelerating`) видає команду керування (прискорення, поворот);
5. коли дрон у точці скиду, виконує скид.

Кроки місії зберігаються в `data/simulation.json`.

Основні компоненти сховані за інтерфейсами (`ITargetProvider`,
`IDronePhysics`, `IBallisticSolver`, `IConfigLoader`) і створюються
фабрикою (`Factory.cpp`), тому та сама логіка місії працює і в локальній
симуляції, і з реальним залізом.

## Режими роботи

**Локальна симуляція** - конфіг, боєприпаси і траєкторії цілей
читаються з JSON у `data/`, фізика дрона рахується всередині програми.

**Віддалений (`--uart`)** - фізику дрона і цілі моделює зовнішній
симулятор-чекер. Програма отримує від нього конфіг, телеметрію і позиції
цілей по UART, відправляє назад команди керування, а сигнали START/DROP
видає через GPIO.

## Технології

| Що | Для чого |
|---|---|
| **C++20**, CMake | мова і збірка |
| **std::thread**, `ThreadSafeQueue`, atomics | окремі потоки для цілей, фізики, телеметрії й місії |
| **UART** (termios, 115200 бод) | власний бінарний протокол (`link/drone_link.h`): кадр `A5 5A | TYPE | LEN | payload | CRC16`, пакети TELEMETRY, TARGET, AMMO, CONFIG, CONTROL, RESULT |
| **GPIO** (libgpiod) | лінія START піднімається на старті, DROP дає імпульс у момент скиду |
| **MAVLink 2 по UDP** (c_library_v2) | HEARTBEAT, GLOBAL_POSITION_INT, ATTITUDE для наземної станції (напр. QGroundControl); про скид повідомляє `COMMAND_LONG` з повторами до отримання `COMMAND_ACK` |
| **HTTP** (сокети POSIX) | відправка результату тесту на сервер курсу з повторами і GET-перевіркою |
| **nlohmann/json** | конфіги, цілі, результати |
| Балістичні солвери | `analytical` (аналітичний розв'язок кубічного рівняння часу падіння) або `table` (інтерполяція по таблиці `data/ballistic_table.txt`) |

## Збірка

Потрібні `libgpiod` і MAVLink headers:

```bash
git clone --depth 1 https://github.com/mavlink/c_library_v2.git drone_hunter/c_library_v2
cmake --preset debug
cmake --build --preset debug
```

## Запуск

```bash
# локальна симуляція
drone_hunter ./data [analytical|table]

# з зовнішнім симулятором по UART + GPIO
drone_hunter --uart /dev/ttyUSB0 [--gpiochip gpiochip1] [--start-line 24] [--drop-line 23]

# до будь-якого режиму:
#   --mavlink <host:port>   куди слати MAVLink (за замовчуванням 127.0.0.1:14550)
#   --test <1..10>          відправити результат на сервер курсу як T01..T10
```
